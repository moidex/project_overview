# Moidex Platform — Обзор архитектуры

## Общее описание

**Moidex** — платформа для управления автомойками, построенная на микросервисной архитектуре. Каждый сервис развёрнут в отдельном контейнере и выполняет изолированную бизнес-функцию: от API-интеграций с внешними партнёрами до обработки заказов, уведомлений и финансовых операций.

---

## Технологический стек

| Категория | Технология | Описание |
|-----------|-----------|----------|
| **Язык** | Python 3.11 | Основной язык платформы |
| **Web-фреймворк** | Flask + Gunicorn / Uvicorn | HTTP-сервер с ASGI-поддержкой для асинхронных операций |
| **База данных** | MongoDB | Основное хранилище данных. Async-доступ через Motor, синхронный — через PyMongo |
| **Кэширование** | Redis | Кэширование данных, хранение сессий и состояния FSM Telegram-бота |
| **Очередь сообщений** | Yandex Message Queue (SQS) | Асинхронная межсервисная коммуникация через aioboto3 |
| **Хостинг** | Yandex Cloud Serverless Containers | Автоматическое масштабирование контейнеров |
| **CI/CD** | GitHub Actions + Docker | Автоматическая сборка, тестирование и деплой |
| **Хранилище секретов** | Yandex Lockbox | Безопасное хранение ключей, токенов и credentials |
| **Логирование** | Yandex Cloud Logging | Централизованный сбор и анализ логов всех сервисов |
| **Холодное хранилище** | Yandex Object Storage (S3) | Хранение файлов, бэкапов и статических ресурсов |
| **Платежи** | YooKassa | Приём и обработка платежей |
| **Telegram** | aiogram 3.7 + aiogram-dialog 2.1 | Telegram-бот для пользователей и персонала |
| **Фронтенд** | Jinja2 + HTMX + Bootstrap | Серверный рендеринг с интерактивными элементами |
| **Валидация** | Pydantic v2, Marshmallow | Валидация и сериализация данных |
| **Документация API** | Flasgger (OpenAPI / Swagger) | Автогенерация документации REST API |

---

## Инфраструктура деплоя

```
GitHub (push) → GitHub Actions → Docker Build (multi-stage) → Yandex Container Registry → Yandex Serverless Containers
```

Каждый микросервис собирается как отдельный target в multi-stage Docker-сборке, что обеспечивает минимальный размер образов и изоляцию зависимостей. Все контейнеры работают с `min_instances >= 1` для минимизации cold start.

## Микросервисы

### 1. Yandex API

**Контейнер:** `yandex_api`
**Порт:** 8080
**Точка входа:** `gunicorn main_yandex_api:asgi_app`

API-сервис для интеграции с платформой Яндекс Заправки. Обеспечивает полный цикл работы с заказами и бронированиями через REST API с аутентификацией по API-ключу.

**Основной функционал:**

- Управление бронированиями (создание, отмена, завершение, истечение)
- Получение списка доступных автомоек
- Создание и отслеживание заказов
- Регистрация станций в системе Яндекс Заправок
- Health-check эндпоинты для мониторинга

**Стек:** Flask, Motor (MongoDB), Gunicorn/Uvicorn (ASGI)
**Количество эндпоинтов:** ~30

---

### 2. External API (TMoidex)

**Контейнер:** `tmoidex`
**Порт:** 8080
**Точка входа:** `gunicorn main_tmoidex:asgi_app`

B2B API-сервис для реализации внешней интеграции партнёров. Предоставляет стандартизированный интерфейс для подключения внешних систем к платформе Moidex.

**Основной функционал:**

- Получение информации об автомойках для внешних систем
- Обработка платёжных вебхуков от партнёров
- Предоставление данных о платежах и статусах

**Стек:** Flask, Motor (MongoDB), Gunicorn/Uvicorn (ASGI)
**Количество эндпоинтов:** ~4

---

### 3. Extended API

**Контейнер:** `crm_extended` (совмещён с CRM)
**Порт:** 8080
**URL-префикс:** `/ext-api/`

API для интеграции партнёрских сетей автомоек в CRM-систему Moidex. Предоставляет расширенный набор эндпоинтов для управления автомойками, заказами и слотами бронирования с встроенным слоем кэширования.

**Основной функционал:**

- Управление списком автомоек партнёрской сети
- Работа с заказами (создание, отслеживание статуса)
- Управление слотами бронирования
- Кэширование данных (TTL 7 минут) для оптимизации производительности
- Аутентификация по API-ключу

**Стек:** Flask, Motor (MongoDB), Redis (кэш), Gunicorn/Uvicorn (ASGI)
**Количество эндпоинтов:** ~17

---

### 4. CRM и фронтенд-модули

#### 4.1 CRM v2

**URL-префикс:** `/crm-v1/`
**Контейнер:** `crm_extended`

Полнофункциональная CRM-система для управления партнёрской сетью автомоек. Предоставляет полный доступ к заказам, управлению мойками, персоналом и тарифами.

**Основной функционал:**

- Управление станциями (создание, редактирование, удаление, мониторинг статуса)
- Полный цикл работы с заказами (CRUD-операции, смена статусов)
- Управление водителями и автомобилями
- Настройка тарифов и ценообразования
- Управление партнёрами и сетями
- Работа с промокодами
- Управление слотами и расписанием

**Стек:** Flask, Jinja2, HTMX, Bootstrap, Motor (MongoDB)
**Количество эндпоинтов:** ~108

#### 4.2 Moidex Lite

**URL-префикс:** `/moidex-lite/`
**Контейнер:** `main`

Облегчённый интерфейс, разработанный специально для мойщиков. Минимальный набор функций без лишних данных — только то, что необходимо для оперативной работы на посту.

**Основной функционал:**

- Просмотр информации о станции и текущих заказах
- Приём и обработка новых заказов
- Переключение статусов заказов (принят → в работе → завершён / отменён)
- Блокировка временных слотов
- Справочник автомобилей

**Стек:** Flask, Flasgger (Swagger), Motor (MongoDB)
**Количество эндпоинтов:** ~14
**Документация:** OpenAPI-спецификация доступна по `/moidex-lite/docs`

#### 4.3 Moidex Booking

**URL-префикс:** `/moidex-booking/`
**Контейнер:** `main`

Модуль собственной онлайн-записи для автомоек. Пользовательский интерфейс для бронирования услуг с расчётом стоимости и выбором доступных слотов.

**Основной функционал:**

- Просмотр информации о станции и доступных услугах
- Получение доступных слотов для бронирования
- Расчёт стоимости услуг
- Создание, просмотр и отмена заказов
- Справочник автомобилей

**Стек:** Flask, Flasgger (Swagger), Motor (MongoDB)
**Количество эндпоинтов:** ~10
**Документация:** OpenAPI-спецификация доступна по `/moidex-booking/docs`

### 5. Админ-панель

**Контейнер:** `main`
**URL-префикс:** `/admin/v2/`

Административная панель для полного управления платформой. Серверный рендеринг с интерактивными элементами через HTMX и Bootstrap. Доступ защищён OAuth-аутентификацией через Яндекс с ролевой моделью доступа.

**Основной функционал:**

- Аутентификация через Яндекс OAuth (ролевая модель: администратор / тестировщик)
- Управление партнёрами (создание, редактирование, просмотр)
- Управление станциями (полный жизненный цикл, мониторинг статуса)
- Управление сетями автомоек (подписки, продление)
- Управление пользователями и водителями
- Просмотр и управление заказами (фильтрация по статусам)
- Создание и управление промокодами
- Статистика и аналитика (рейтинги, тепловые карты тарифов)
- Управление настройками платформы и cron-задачами

**Стек:** Flask, Jinja2, HTMX, Bootstrap, Motor (MongoDB), Yandex OAuth
**Количество эндпоинтов:** ~77

---

### 6. Демон обработки заказов

**Контейнер:** `order_processing_daemon`
**Точка входа:** `python3 worker_order_processing.py`

Асинхронный воркер для обработки переходов состояний заказов и платёжных операций. Получает задачи из очереди сообщений Yandex Message Queue (SQS-совместимый протокол) и маршрутизирует их по типу операции.

**Основной функционал:**

- Обработка бронирований (`to_process_order_booking`)
- Обработка платежей (`to_process_order_payment`)
- Обработка заказов собственных станций (`to_process_own_order_booking`)
- Обработка ошибок с перемещением в Dead Letter Queue (DLQ)
- Поддержка парсинга сообщений в форматах JSON и Python literal

**Стек:** asyncio, aioboto3 (SQS), Motor (MongoDB)

---

### 7. Демон Telegram и уведомлений

**Контейнер:** `telegram_daemon`
**Точка входа:** `python3 worker_telegram.py`

Telegram-бот для взаимодействия с пользователями и персоналом автомоек, а также система уведомлений через множество каналов. Обрабатывает сообщения из очереди и Telegram webhook.

**Основной функционал:**

- Пользовательская зона: меню, диалоги, обучающие модули по бронированию
- Зона персонала: интерфейс для водителей и менеджеров
- Уведомления о статусах заказов (Pulse Notifications)
- Push-уведомления через Expo Push SDK
- Отправка email-уведомлений через SMTP
- Генерация отчётов в формате XLSX
- Обработка политики отмены заказов
- Интеграция с Max messenger (обработка вебхуков)

**Стек:** aiogram 3.7, aiogram-dialog 2.1, Redis (FSM-хранилище), Motor (MongoDB), Expo Push SDK, SMTP

---

### 8. Демон финансовых документов

**Контейнер:** `fin_docs_daemon`
**Точка входа:** `python3 worker_fin_docs.py`

Воркер для обработки финансовых операций B2B-функционала. Создаёт аудитируемые документы для всех финансовых транзакций с партнёрами, обеспечивая полную прозрачность и прослеживаемость движения средств.

**Основной функционал:**

- Создание счетов (`create_invoice`)
- Фиксация платежей (`create_payment`)
- Обработка возвратов (`create_refund`)
- Создание выводов средств (`create_withdraw`)
- Отслеживание баланса партнёра (до и после операции)
- Генерация уникальных идентификаторов документов (UUID)

**Стек:** asyncio, aioboto3 (SQS), Motor (MongoDB)

---

### 9. Cron-задачи

**Контейнер:** `cron_main`
**Точка входа:** `python3 cron_launcher.py`

Планировщик периодических задач. Задачи диспетчеризуются через payload из Yandex Message Queue и выполняются по расписанию (ежечасно, ежедневно, еженедельно).

**Основной функционал:**

- Расчёт метрик производительности станций (лучшие / худшие)
- Обновление скоринга релевантности заказов
- Агрегация статистики по заказам
- Формирование ежедневной статистики станций
- Автоматическое продление подписок партнёров
- Синхронизация статусов очередей с системой Pulse-уведомлений
- Валидация консистентности данных
- Очистка истёкших блокировок слотов
- Массовая рассылка сообщений
- Импорт и синхронизация станций TMoidex

**Стек:** asyncio, Motor (MongoDB), aioboto3 (SQS)

---

### 10. Heartbeat-мониторинг

**Контейнер:** `heartbeat_daemon`
**Точка входа:** `python3 worker_heartbeat.py`

Сервис мониторинга состояния и доступности всех контейнеров платформы. Обеспечивает контроль работоспособности микросервисов и своевременное обнаружение сбоев.

**Стек:** asyncio, HTTP-клиент

## Инфраструктурные сервисы Yandex Cloud

| Сервис | Назначение |
|--------|-----------|
| **Serverless Containers** | Хостинг всех микросервисов с автоматическим масштабированием |
| **Container Registry** | Хранение Docker-образов |
| **Message Queue** | SQS-совместимая очередь для межсервисной коммуникации |
| **Lockbox** | Безопасное хранение секретов (API-ключи, токены, credentials) |
| **Cloud Logging** | Централизованное логирование всех сервисов |
| **Object Storage (S3)** | Холодное хранилище файлов, бэкапов и статики |
| **API Gateway** | Маршрутизация трафика, canary-деплой (10% на prestable) |
