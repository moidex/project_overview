## Архитектура платформы Moidex (кратко)

Платформа построена на микросервисной архитектуре с разделением на API-слой, CRM/клиентские интерфейсы и асинхронные воркеры.

### Основной поток данных

- внешние системы (включая Яндекс) работают через отдельный API-сервис  
- заказы и события попадают в очередь (Yandex Message Queue)  
- воркеры обрабатывают их асинхронно (заказы, платежи, уведомления)  
- данные хранятся в MongoDB, кэш — Redis  

### Масштабирование и отказоустойчивость

Это позволяет:
- независимо масштабировать части системы (например, обработку заказов или API)  
- изолировать нагрузку между сервисами  
- обрабатывать пики через очередь без деградации системы  

### Клиентский слой

Клиентская часть (CRM, mobile, booking) работает через единый backend API, при этом логика разделена по доменам:
- заказы  
- станции  
- тарифы  
- пользователи  


Для корректной работы система требует доступ к инфраструктуре и сервисам, развернутым в Яндекс Cloud.

## Используемые сервисы

- **Управляемая (managed) база данных MongoDB**
- **Управляемый (managed) Redis** для кэширования
- **Yandex Message Queue** — для асинхронного взаимодействия сервисов
- **Yandex Object Storage** — для хранения файлов и бэкапов
- **Yandex Cloud Logging, Lockbox** — для логирования и хранения секретов
- Интеграции с внешними API (включая Яндекс и платёжные системы)

## Архитектурные особенности

Вся инфраструктура централизованно размещена в Яндекс Cloud.

Ключевые компоненты (включая базы данных и кэш) используются в формате managed-сервисов, что исключает необходимость их самостоятельного администрирования.

Архитектура изолирована и полностью управляется в рамках облачной среды, без зависимости от сторонних систем вне данного контура.
